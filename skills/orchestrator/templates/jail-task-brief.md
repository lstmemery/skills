Copy this template and replace every `{{...}}` value before launch. Keep the
worker result schema and jail import declaration as separate records. The
pre-launch inventory below lists expected output filenames and the files that
must already be present in the staged bundle.

## Jail pre-launch inventory

Before spending a jail attempt, stage the required files in `{{bundle-root}}`
and run the preflight command below. Inventory input paths are relative to that
bundle root. `artifact_paths` are the flat filenames expected under
`/work/out/`; the validator checks their import-safe shape, not whether those
future outputs already exist. Declare at least one production input, test
input, and fixture input. List every reused report or other prior output in
`prior_inputs`.

```json jail-preflight
{
  "schema": 1,
  "artifact_paths": [
    "{{report-filename}}",
    "{{worker-result-filename}}"
  ],
  "production_inputs": ["{{bundle-relative-production-file}}"],
  "test_inputs": ["{{bundle-relative-test-file}}"],
  "fixture_inputs": ["{{bundle-relative-fixture-file}}"],
  "prior_inputs": []
}
```

Run from the orchestrator skill directory. This must pass before launching the
jail worker:

```sh
python3 scripts/worker-records.py check-brief --jail \
  --bundle-root "{{bundle-root}}" "{{brief-path}}"
```

## Output

Write each declared output file under `/work/out/`. Write the worker `result`
record as one of those artifacts, then write the jail import declaration last
to `/work/out/.runs/{{run-id}}/result.json`. Do not put the import declaration
itself in `artifact_paths`. Compute each declaration hash from the final file
bytes. Do not create publish or queue markers.

## Worker result record (generated by `worker-records.py schema --format md`)

Copy this whole section verbatim into each worker brief or per-run CONTRACT. Do not rewrite the example or allowed values.

```json
{
  "task_id": "task-id",
  "assignment_revision": 1,
  "outcome": "ready",
  "summary": "What was produced and what it establishes.",
  "artifacts": [
    {
      "path": "artifact-path",
      "kind": "report"
    }
  ],
  "checks": [
    {
      "name": "check",
      "status": "passed",
      "evidence": "evidence-path"
    }
  ],
  "unresolved": [],
  "next_action": "Present the artifact to the user."
}
```

Required top-level fields: `task_id`, `assignment_revision`, `outcome`, `summary`, `artifacts`, `checks`, `unresolved`, `next_action`.
Optional top-level fields: `candidate`; omit `candidate` for non-repository tasks.
`outcome` must be one of `blocked`, `failed`, `partial`, `ready`; `assignment_revision` must be an integer from 1 to 9223372036854775807.
Brief outcomes map to this field as follows: `success` -> `ready`, `ask` or `blocked` -> `blocked`, `partial` -> `partial`, and `failed` -> `failed`.
`task_id` and `assignment_revision` must match the identity supplied to `validate-result`.
Text values must be non-empty strings with no NUL and at most 100,000 characters.
`artifacts` is an array of objects with exactly `path`, `kind`; it may be empty only when the outcome is not `ready`.
`checks` is an array of objects with exactly `name`, `status`, `evidence`; `status` must be one of `failed`, `not_run`, `passed`.
`checks[].evidence` must be a non-empty string, such as a path or concise check result.
`unresolved` is an array of non-empty strings; `partial`, `blocked`, and `failed` require at least one explanatory item.
Validate each result with this command from the orchestrator skill directory:

```sh
python3 scripts/worker-records.py validate-result "$WORKER_DIR/result.json" --task-id "$TASK_ID" --revision "$REVISION"
```

For repository changes, validate with `--repository-changes` and include `candidate` with exactly `repo`, `branch`, `base`, `head`.
When present, `candidate` must be an object with non-empty string values.
Unknown fields and duplicate JSON keys are invalid.

Repository-change candidate shape:

```json
{
  "candidate": {
    "repo": "repo-value",
    "branch": "branch-value",
    "base": "base-value",
    "head": "head-value"
  }
}
```

## Jail import declaration (schema 1; validated by `tools/pii-jail/stage-run-artifacts.py`)

The worker result record above describes the worker's findings and checks. The
separate jail import declaration lists only files to import and their lowercase
SHA-256 digests. It is written after those files are final. Each artifact path
is one filename directly under `/work/out/`; the declaration file itself is
metadata and is not imported.

This is a valid declaration example. The digest matches `example-report.md`
containing exactly `Example report.` followed by a newline. Replace it with
hashes for the actual final artifacts.

<!-- jail-import-example:start -->
```json
{
  "schema": 1,
  "artifacts": [
    {
      "path": "example-report.md",
      "sha256": "445e0234ea41ef75a7da9d144a64abac0d09bee7e206dd2386cb68c6a84f531c"
    }
  ]
}
```
